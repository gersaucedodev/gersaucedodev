## 🧠 Cómo trabajo

- **Código legible antes que código ingenioso.** Nombres claros, funciones cortas y una sola responsabilidad por módulo.
- **Control de versiones siempre.** Commits pequeños y descriptivos, ramas por funcionalidad y nada de credenciales en el repositorio (uso de `.env` y `.env.example`).
- **Datos bien modelados.** Un buen esquema de base de datos y migraciones versionadas evitan la mayoría de los problemas futuros.
- **Automatizar lo repetitivo.** Si una tarea se hace a mano más de dos veces, probablemente merece un script o un flujo.
- **Pensar en el usuario final.** Mi trabajo en soporte me recuerda todos los días que el software lo usan personas, no solo otros programadores.
- **Documentar para el que viene.** Cada proyecto con su README: qué hace, cómo se instala y cómo se usa.
